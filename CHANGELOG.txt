DocFlow — история изменений
================================

Версия отображается в заголовке окна и в правом верхнем углу (клик — «О программе»).


v1.12.2 — 2026-07-28
--------------------
- Поиск ЭЦП в первую очередь выполняется в каталогах версий `4300_ПД`.
  Учитываются подписи как внутри `!PUBLISHED`, так и непосредственно в каталоге
  версии, включая схему имени `документ_Фамилия.sig` без повторения `.pdf`.
- Добавлены «Быстрая проверка» и «Полная проверка». Быстрая использует общий
  индекс, повторно читает файлы только в изменившихся каталогах и обрабатывает
  независимые источники в четырёх параллельных потоках.
- Общий результат показывается сразу, актуализация продолжается в фоне. Пока она
  идёт, в верхней строке отображается «Фоновая проверка», а индикатор активен.
- В настройках проекта добавлено окно «Подписанты ЭЦП»: пользователи могут
  выбрать документ, внести фамилии или ФИО и задать режим «не проверять»,
  «предупреждение» или «ошибка» без ручного редактирования JSON.
- Исправлена значимость проверки подписей: общий перевод проверки в режим
  «ошибка» теперь действительно повышает отсутствующие подписи до ошибки.
- Повторная проверка !LATEST ускорена: CRC32 пересчитывается только для файлов,
  у которых изменились размер или время изменения; общий кэш хранится в
  .docflow_crc.json и используется всеми пользователями проекта.
- Снимок сканирования .docflow_state.json перенесён в корень проекта и стал общим
  для пользователей. Запись общего снимка и CRC-кэша выполняется атомарно.


v1.12.1 — 2026-07-27
--------------------
- Исправлен аудит имён каталогов версий: папка вида
  «523-ПИР-24-ТХ1_Раздел ПД №6 Часть №1_260727» теперь предлагается к
  переименованию в «523-ПИР-24-ТХ1_260727».
- XML добавлен в штатные публикуемые форматы, в том числе для ранее сохранённых
  настроек проектов; корректный XML из состава больше не помечается замечанием.
- В окне !LATEST добавлена проверка актуальности XML пояснительной записки:
  программа сверяет версию ПЗ с версиями упомянутых файлов в комплекте и
  показывает документы, из-за которых ПЗ требуется обновить. При одинаковой
  дате дополнительно проверяется перезапись файла по CRC32.
- В состав проекта добавлено поле `signers` — перечень обязательных подписантов
  ЭЦП для каждого документа. Аудит проверяет наличие подписи каждого указанного
  подписанта у каждого публикуемого файла и показывает недостающие подписи.
  Строгость задаётся полем `signature_level`: `none` — не проверять, `warn` —
  замечание комплектности (по умолчанию), `error` — критично для окончательного
  комплекта.
- В контекстное меню замечания добавлено действие «Добавить папку замечания в
  исключения». Папка автоматически записывается в настройки проекта, после чего
  проверка запускается повторно.


v1.12.0 — 2026-07-27
--------------------
- Выбор файлов для подписания расширен до полной иерархии: 4300_ПД/1100_ИИ,
  разделы и отдельные тома. Дерево открывается отдельной кнопкой во всплывающем
  окне; родительский флажок переключает всю ветку, по умолчанию выбраны все тома.
- Полный текст замечания теперь показывается в растягиваемой панели под таблицей
  действий — длинные пояснения можно прочитать без обрезки.
- Проверки структуры 4300_ПД и папок субподрядчиков переведены на единые правила
  аудита: одинаково обрабатываются служебные папки, исключения и каталоги версий.
- При переносе версии существующая папка на сервере заменяется атомарно, без
  смешивания старых и новых файлов.
- Исправлено сканирование после разделения интерфейса на модули: кнопка
  «Сканировать» снова запускает проверку и не оставляет окно в занятом состоянии.
- Уточнена обработка ошибок при работе с файлами и папками; сообщения стали
  понятнее, а запись журнала — надёжнее.
v1.11.2 — 2026-07-19
--------------------
- Исправлено сравнение !LATEST с 4300_ПД: если файл в 4300_ПД переписали
  внутри той же папки версии (дата в имени папки не менялась), сравнение
  раньше молча показывало «🟢 в порядке» — расхождение не было видно. Теперь
  при совпадающей дате версии дополнительно сверяется содержимое файлов по
  CRC32 (как уже было при переносе от субподрядчика); при расхождении —
  статус 🟣 «та же версия, но файлы отличаются», двойной клик по строке
  показывает, какой именно файл изменён/добавлен/пропал.

v1.11.0 — 2026-07-03
--------------------
- Новая кнопка «♊ Дубликаты» — поиск одинаковых по содержимому файлов (CRC32)
  в захламлённой папке. Сначала группировка по размеру, затем сверка CRC32
  (совпал размер и CRC32 ⇒ файлы идентичны — разные имена не мешают).
  • У каждого файла показывается ДАТА И ВРЕМЯ, размер и расположение.
  • По умолчанию оставляется самая РАННЯЯ копия. При ОДИНАКОВОМ времени
    приоритет у копии, которая уже в каталоге версии (её не двигаем).
    Клик по файлу меняет выбор.
  • Группы отмечаются галочкой (☑/☐) + «Выбрать все / Снять все» — можно
    обрабатывать точечно только нужные группы.
  • Заменить в каталоге версии: если оставляемая копия лежит ВНЕ каталога
    версии, а её двойник — в каталоге {обозначение}_{дата}, ранняя копия
    ставится в каталог версии (с нужным именем ⇄), поздняя убирается.
  • «Удалить» = перенос лишних копий в папку !УДАЛЕННЫЕ (плоско, без вложенных
    папок; не Корзина, не безвозвратно) — вернуть можно «Откатить последнее».
  • Файлы в !ARCHIVE НЕ трогаются: если такая же копия уже есть в !ARCHIVE —
    программа только УВЕДОМЛЯЕТ (ℹ «есть в !ARCHIVE»), актуальную копию не
    удаляет и архив не меняет. Галочка «Пропускать !ARCHIVE» — не сканировать
    архив вовсе.
  • После «Применить» повторный список открывается без галочек (чтобы не
    сработало повторно). Уведомления по !ARCHIVE по умолчанию не отмечены.
  • Показывает число групп, уведомлений, выбрано, лишних копий и объём.

v1.10.0 — 2026-07-02
--------------------
- Новая кнопка «✍ Подписание» — конвейер подписания комплекта в три шага:
  1) СОБРАТЬ на подпись: из !LATEST / 4300_ПД / 1100_ИИ (любой структурной
     папки) актуальные файлы каждого документа (pdf, xml, gge — настраивается)
     собираются в ОДНУ плоскую папку. Редактируемые исходники (!EDIT) не берутся.
  2) ДОБАВИТЬ ФАМИЛИЮ: после подписания к каждому .sig добавляется фамилия
     (523-…Часть №1.pdf.sig → …Часть №1.pdf_Сидоров.sig). Повторный запуск
     ничего не портит; для нескольких подписантов — по очереди на каждую партию.
  3) РАЗЛОЖИТЬ .sig — два варианта:
     • А (наши подписи): по имени сопоставляются с документом и кладутся в
       !PUBLISHED самой свежей версии на сервере (КР1/КР10 не путаются);
     • Б (подписи от субподрядчика): раскладываются в указанную папку рядом с
       файлом того же имени (X.pdf.sig → рядом с X.pdf в этой папке/подпапках);
       версии в !ARCHIVE пропускаются, ненайденные файлы отмечаются.
- Столбцы «Организация» и «Ответственное лицо» перенесены сразу после
  «Наименование» (перед техническими «Актуальная версия» / «Наименование файла»).

v1.9.0 — 2026-07-02
-------------------
- Виды/тома изысканий больше НЕ зашиты в программе: состав ИИ берётся с диска —
  любая папка «NN_XXX» (01_ИГДИ, 08_ТО …) становится разделом. 08_ТО и прочие
  тома учитываются автоматически. (Пересоберите состав проекта, чтобы применить.)
- В стандартную форму реестра возвращены столбцы «Организация» и «Ответственное
  лицо» (после «Наименование файла»); все 6 реестров и шаблон обновлены.
- Проверка субподрядных папок и изысканий теперь ловит лишние/неверно
  названные папки: тупиковая папка без документов из состава помечается
  «лишняя папка», каталог версии с неверным именем — «нет в составе».
- Служебные файлы программы (.docflow_crc.json, .docflow_latest.json и любые
  скрытые «.») игнорируются ВСЕГДА — больше не попадают в замечания.
- Вложенность комплекта !LATEST настраивается (Проект → «Вложенность в !LATEST»):
  плейсхолдеры {area}/{section}/{razdel}/{short}/{oboznachenie}. Проверка
  «лишнего» в !LATEST работает при любой вложенности.
- Двойной клик по документу в окне «Перенос на сервер» — пофайловое сравнение
  папок субподряда и сервера по CRC32: видно, какие файлы где, их CRC32 и
  вердикт (совпадает / переписан / переименован / только у одной стороны).
